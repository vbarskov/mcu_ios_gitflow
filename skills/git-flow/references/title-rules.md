# Заголовки УЗС и КЗС

Источник: [«Требования процесса разработки», IVA Wiki](https://wiki.iva.ru/spaces/IVCS/pages/72588399/Требования+процесса+разработки). Правила заголовков проверены 3 ноября 2026 года. Этот документ описывает оформление заголовков и не меняет разрешения на сборки, проверки приложения или слияние.

Порядок компонентов: `!номерЗС #числоJira`, маркеры ветки и типа ЗС, название фичи при наличии, русское действие в инфинитиве, `reopened` при новой серии после переоткрытия, `№части.`, затем краткий фактический итог УЗС или `Контроль` для КЗС. Квадратные скобки к маркерам не добавляются.

- `🐥20.2` — если выбранное назначение `minor/20.2`. Для КЗС учитывается фактически выбранная `kzsBaseBranch`.
- `💀` — для каждого УЗС.
- `🐬` — только для КЗС в ГЗС. Для КЗС в `release/` его нет и `kzsTargetIsGzs` должен быть `false`. Статус ГЗС задаётся полем `kzsTargetIsGzs`, а не догадкой по названию ветки. Если для назначения вне release в карточке и беседе нет явного подтверждения или отрицания ГЗС, уточните это у автора до оформления. Для сообщения в чат этот маркер ставится только в первой строке; во второй после `√` его нет. Если автор одновременно указал release/ и ГЗС, это конфликт входных данных: уточните назначение до публикации, не выбирайте маркер молча.
- `featureName` — отдельное поле для названия фичи при наличии. Чтобы убрать ранее сохранённую фичу, передайте `featureName: ""`; пропуск поля не очищает его.
- `reopened: true` — только для новой серии после переоткрытия задачи. Это установленный Wiki технический маркер; остальной текст пишется по-русски, идентификаторы продуктов допустимы.
- `uzsPartNumber` и `kzsPartNumber` — реальные положительные номера частей. По умолчанию УЗС имеет №1, КЗС — следующую часть; для иной серии сохраните её номера.

Примеры из требований:

```text
!9999 #9999 💀 Что-то сделать №1. Краткое описание
!9999 #9999 🐥20.2 💀 Что-то сделать №2. Дубль в минор
!9999 #9999 Что-то сделать №3. Контроль
!9999 #9999 🐬 Что-то сделать №3. Контроль
```

В `mcu_update_task.title` передаётся только русское действие в инфинитиве. Префикс, фича, маркеры, номер части и окончание добавляются форматтером из отдельных полей. В `done` сохраняется одна короткая строка о фактически выполненном изменении на русском; она добавляется в заголовок УЗС после точки. Длинный отчёт хранится в `result`, `changes` и `verification`.

Для нового запроса номер MR ещё неизвестен: preview показывает `!<номер>`, а опубликованный заголовок получает реальный номер. Проверяйте итоговый заголовок в preview. Максимальная длина — 255 символов: при превышении сократите формулировку вручную и получите новый preview; молчаливое обрезание запрещено.

## Существующий родительский ГЗС

Родительский ГЗС — отдельный MR со своим названием и, возможно, несколькими Jira. Например, автор указал:

```text
!319 #15815 #15835 #15836 #15838 #15839 🐬 Добавить настройки мероприятий и комнат при планировании и редактировании. Гигант
```

Сохраняйте исходный заголовок целиком и полный набор Jira, включая все пять номеров этого примера. Не заменяйте их текущей задачей и не выбирайте первую Jira основной по позиции; при необходимости основной задачи без контекста спросите автора. Правила форматтера текущего УЗС/КЗС не являются поручением переименовать ГЗС.

Для привязки используйте только `mcu_attach_gzs {taskId, iid}`: GET существующего MR и локальное сохранение в `task.gzs` вместе с `jiraNumbers`/`jiraKeys`, без изменения GitLab. `GZS.source_branch` сверяется с действующим назначением: фактическим `KZS.target_branch`, а при его отсутствии — подтверждённой базой КЗС или текущим назначением. `GZS.target_branch` обычно release и не обязан совпадать с назначением КЗС. Привязка подтверждает ГЗС для совпавшего назначения вне release; текущие УЗС/КЗС сохраняют собственную Jira. `mcu_attach` с `kind: uzs/kzs` для родительского ГЗС не подходит. Создание, публикация и слияние ГЗС этим не выполняются.
