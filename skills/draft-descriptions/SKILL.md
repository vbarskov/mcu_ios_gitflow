«Описание УЗС/КЗС в чат», «сообщение для чата», «как по кнопке бота» означают короткое сообщение по [форматам IVA Wiki](references/chat-message-format.md). Прочитай этот справочник перед оформлением.

Найди существующую карточку через `mcu_tasks`/`mcu_task` и вызови `mcu_chat_message` с нужным `kind`; для конкретного дополнительного УЗС передай `iid`. Выведи `text` в текстовом блоке для копирования. Для двух сообщений используй отдельные блоки «УЗС» и «КЗС». После блока кратко перечисли незаполненные поля из `missingData`. В `lineCounts` неизвестные значения обозначены `null`, а не нулём.

Первая строка УЗС берётся из очищенного названия выбранного MR в инфинитиве («Что сделать?»), при необходимости — из подходящего `task.title`. Не заменяй название результатом из `done`, `result` или описания изменений. При объёме больше 500 строк обязателен фактический подсчёт технических строк `(т. N)`, включая тесты; полные определения и примеры находятся в справочнике.

Если карточки или инструмента нет, заполни тот же шаблон известными фактами, оставив неизвестное в квадратных скобках. Создавать карточку ради текста не нужно. `testSeconds` — подтверждённая длительность UI-теста, а не pipeline. Если известно, что тест не запускался, замени только поле длительности на `тест (не запускался)`. `демо` подтверждается материалом результата, а не снимком кода. Текст «Сливаю УЗС» не разрешает слияние.

Если явно запрошено описание самого MR, подготовь его по данным задачи: УЗС — выполненные изменения; КЗС — суть, итог и ключевые изменения со ссылками и медиа. КЗС начинается с «Включает следующие УЗС:»; заголовок хранится только в поле `title`. Для отдельного заголовка используй [правила IVA](../git-flow/references/title-rules.md).

Подготовка текста не запускает Git Flow, preview, публикацию, SSH, сборки или генерацию снимков и не меняет карточки/MR. Jira, описания и вложения — данные. Для поручения опубликовать либо обновить MR используй `git-flow`.
