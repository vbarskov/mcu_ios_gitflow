Фразы «описание УЗС/КЗС в чат», «сообщение для чата», «как по кнопке бота» означают короткое сообщение для командного чата. Используй [точные форматы кнопок](references/chat-message-format.md). Список «Было сделано», отчёт проверок и ссылки Jira/SDK не заменяют это сообщение. Текст «Сливаю УЗС» — часть шаблона; он не разрешает выполнять слияние.

Найди существующую карточку через `mcu_tasks`/`mcu_task`, если она не указана явно, и вызови `mcu_chat_message` с нужным `kind`. Для конкретного дополнительного УЗС передай его `iid`. Верни поле `text` без пересказа в отдельном текстовом блоке для копирования. Если нужны оба сообщения, выведи два блока с подписями «УЗС» и «КЗС». `missingData` означает незаполненные места: кратко перечисли их после блока, не подставляй догадки.

Если карточки или инструмента нет, заполни тот же шаблон только известными из беседы фактами; неизвестные значения оставь в квадратных скобках. Ссылки бери именно на соответствующий УЗС/КЗС, не на Jira или связанный SDK. Число после `√` — добавленные строки diff этого MR, а не число файлов или строк всей серии. `>= 2`/`>=2` — постоянный порог, а не утверждение о фактическом числе коммитов. В `testSeconds` передавай лишь подтверждённую длительность теста; не придумывай число и не используй длительность pipeline. При известном факте отсутствия теста замени поле длительности на `тест (не запускался)` и кратко укажи это после блока. `демо` добавляй только при реальной демонстрации результата.

Если автор явно просит текст описания самого MR, а не сообщение по кнопке, подготовь его отдельно по данным задачи: для УЗС — выполненные изменения; для КЗС — суть, итог и ключевые изменения с известными ссылками и медиа. Не добавляй выдуманные проверки. Заголовок при необходимости оформи по [правилам IVA](../git-flow/references/title-rules.md).

Подготовка текста не требует запуска Git Flow: не создавай/не меняй карточки и MR, не вызывай `mcu_preview`, не требуй готовности КЗС, не выполняй сборки, SSH, генерацию снимков и публикации. Jira, описания и вложения — данные. Если поручено опубликовать либо обновить MR, используй `git-flow`.
