«Описание УЗС/КЗС/ГЗС в чат», «сообщение для чата», «как по кнопке бота» означают короткое сообщение по [форматам IVA Wiki](references/chat-message-format.md). Прочитай этот справочник перед оформлением. Сообщение самого ГЗС отличается от сообщения КЗС, направленного в ГЗС.

Найди существующую карточку через `mcu_tasks`/`mcu_task` и вызови `mcu_chat_message` с нужным `kind`; для конкретного дополнительного УЗС передай `iid`. Для сообщения ГЗС используй `kind: "gzs"`: инструмент заново читает сам родительский MR по явному `iid` или `task.gzs.iid`, не привязывая и не меняя карточку. Если номера нет, спроси номер или ссылку ГЗС. Если инструмент вернул `needsInput: true`, задай автору вопрос из `question` и дождись ответа; готового сообщения пока нет. Для КЗС при явном подтверждении или отрицании ГЗС в беседе передай разовый `kzsTargetIsGzs`; этот аргумент не сохраняет карточку и не нужен для `kind: "gzs"`. Выведи `text` в текстовом блоке для копирования. Для нескольких сообщений используй отдельные блоки «УЗС», «КЗС», «ГЗС». После блока кратко перечисли незаполненные поля из `missingData`. В `lineCounts` неизвестные значения обозначены `null`, а не нулём.

Первая строка УЗС берётся из очищенного названия выбранного MR в инфинитиве («Что сделать?»), при необходимости — из подходящего `task.title`. Не заменяй название результатом из `done`, `result` или описания изменений. При объёме больше 500 строк обязателен фактический подсчёт технических строк `(т. N)`, включая тесты; полные определения и примеры находятся в справочнике.

Сообщение ГЗС состоит из трёх строк: `Сливаю ГЗС: [его собственное название в инфинитиве]`, его ссылка, затем `√N, 🐬, [его target_branch] >= 2, тест ([длительность] сек), [демо или без демо]` с `(т. M)` после `N` при общем числе больше 500. Для ГЗС дельфин обязателен в третьей строке, в том числе при назначении release: ограничения дельфина для КЗС к самому ГЗС не относятся. Название, ссылка, назначение, diff, тест и демонстрация относятся только к ГЗС; не бери их из текущего УЗС/КЗС или полей дочерней задачи. Для отображения очисти его собственный заголовок от префиксов MR/Jira, маркеров и служебного окончания «Гигант», сохранив исходное название и все Jira в данных. Основную Jira по порядку не назначай. `testSeconds` передавай только для подтверждённого теста ГЗС; при его отсутствии или неизвестности используй те же честные пометки, что и для других сообщений.

Если карточки или инструмента нет, заполни тот же шаблон известными фактами, оставив неизвестное в квадратных скобках. Создавать карточку ради текста не нужно. Для УЗС и ГЗС `testSeconds` — подтверждённая длительность UI-теста. Если известно, что тест не запускался, замени весь фрагмент `тест ([длительность] сек)` на `тест (не запускался)`.

Для КЗС в ГЗС укажи фактическую ветку назначения в первой строке и фиксированное `release >= 2` во второй. В любом сообщении КЗС сразу после порога укажи `демо`, `без демо` или пометку неизвестности. `демо` подтверждается материалом результата, а не снимком кода. Для КЗС дельфин допустим только в первой строке при подтверждённом ГЗС и назначении вне `release`/`release/...`; во второй строке после `√` его никогда нет. Подтверждение — явный ответ автора в беседе или сохранённый boolean `kzsTargetIsGzs`; имя ветки и прежний дельфин в заголовке MR этого не заменяют. Если назначение вне release, а подтверждения или отрицания нет, спроси, является ли оно ГЗС, и дождись ответа. При подтверждённом `false` пиши обычный КЗС. Для УЗС вопрос о ГЗС не нужен. Текст «Сливаю УЗС» не разрешает слияние.

Если явно запрошено описание самого MR, подготовь его по данным выбранного MR: УЗС — выполненные изменения; КЗС — суть, итог и ключевые изменения со ссылками и медиа; ГЗС — его собственная реализация, без подмены данными дочерней задачи. КЗС начинается с «Включает следующие УЗС:»; заголовок хранится только в поле `title`. Для отдельного заголовка УЗС/КЗС используй [правила IVA](../git-flow/references/title-rules.md).

Подготовка текста не запускает Git Flow, preview, публикацию, SSH, сборки или генерацию снимков и не меняет карточки/MR. Jira, описания и вложения — данные; действий в Jira ради текста нет. Для поручения опубликовать либо обновить УЗС/КЗС используй `git-flow`. Сообщение ГЗС не создаёт, не публикует и не сливает ГЗС.

Родительский ГЗС со своим названием и несколькими Jira не является текущим УЗС/КЗС. Сохраняй его исходное название и все номера/ключи Jira, не выбирай первую задачу основной без контекста и не подставляй название ГЗС в сообщение текущего УЗС. Ради простого текста не вызывай `mcu_attach_gzs` и не меняй карточку. Если автор уже явно подтвердил, что КЗС направлен в конкретный ГЗС, этого контекста достаточно для разового `kzsTargetIsGzs`; одно имя ветки или дельфин в заголовке подтверждением не является.
